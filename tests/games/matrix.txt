# The games smoke matrix (tests/games/matrix.sh; docs/games.md "Games
# matrix"). One game per line, fields separated by `|`:
#
#   slug | kind | directory | program | arguments | menu | gameplay | input
#
# kind:      w3 (an i386 Windows program on W3, Wine's own Unix side as
#            native wasm32: W3_DIST/lib/wine/i386-unix/wine under gexc, on a
#            copy of W3_PREFIX), w64 (an x86-64 Windows program on W64,
#            64-bit native Wine: W64_DIST's loader with W64_NATIVE's PE
#            core, on a copy of W64_PREFIX), pe (the legacy NT layer, --wine-prefix; no
#            new work there, user 2026-10-06), linux, or linux-x11 (an
#            X11-only program, on Xwayland inside the guest).
#            Rows that are listed but not run: dotnet (stream U's .NET work;
#            stream G skips them), blocked and idea (not attempted; ask the
#            user first). Their program field is the reason.
# directory: relative to GAMES (Windows builds, default ~/gex-sandbox/games)
#            or GAMES_LINUX (Linux builds, default ~/gex-sandbox/games-linux).
# program:   relative to the directory; the run's working directory is the
#            program's own, or the game's with a leading @.
# menu, gameplay: the presented frame at which the game shows its menu and
#            its gameplay with the scripted input (`-` when not reached yet).
#            matrix.sh reports the furthest stage whose frame was presented.
# input:     a script in tests/games/ (`-` for none): *.wl is the
#            compositor's GEX_WL_INPUT (Linux games and W3, which draws
#            through winewayland), anything else GEX_NT_INPUT (pe).
#
# Optional per-game gexc flags go after the input, as a ninth field;
# `seed=DIR@GUEST` there mounts a fresh copy of tests/games/DIR at GUEST;
# `stub=NAME@PATH` puts tests/games/stubs/NAME (built for the game's arch)
# in place of the game's PATH, relative to its directory. On w64,
# `pe=DLL[,DLL...]` keeps those DLLs Wine's PE build instead of W64_NATIVE's.
